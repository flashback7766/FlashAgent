# Audit: dead code and bugs

Date: 2026-10-21. Tree: `model-contract`, `0d9e57f` (after track C).
Scope: 132 files, 85 423 lines in `crates/`.

What was looked for, and with what:

* `cargo clippy` with the `correctness`, `suspicious`, `complexity`, `perf`,
  `nursery`, `unreachable_pub` lint sets — on top of the usual `-D warnings`;
* a script of our own over the sources: the definitions of `pub` items, the
  enum variants and the struct fields that nobody reads; identical function
  bodies;
* `rg` passes over the dangerous constructs: `unwrap`/`expect` outside tests,
  slices with computed bounds, locks carried across `await`, integer
  overflow;
* the translation table: 889 pairs — none empty, no duplicates, no repeated
  keys;
* five parallel deep readings, one per crate: `core`, `llm`, `tui`
  (the app flow), `tui` (the rendering and the panels), `tools` + `svc`;
* every finding was checked by reading the surrounding code; some by running
  it (probes in `/tmp`, the repository was left alone).

Nothing was fixed. All the findings are for reading.

## 1. Bugs

### 1.1 [critical] `crates/tools/src/fs_tools.rs:411` — `edit_file` panics when the edits are listed out of order

`plan_all_edits` (`fs_tools.rs:435`) plans every edit against the **original**
text, but applies them in a loop `for planned in planned.into_iter().rev()` —
that is, in reverse **array** order, not in reverse text order.
The offsets are correct only if the order of the array matches the order of
the edits in the file.

Checked with a probe (the real `BuiltinTools::edit_file`):

```
edits: [{old: "line two"}, {old: "line one"}]   // the model listed them bottom-up
→ panicked at library/core/src/slice/index.rs:1009:51:
  range end index 17 out of range for slice of length 13
```

If the offsets stay in range — silent corruption: "TARGET2" became "TARGETX",
and the tool reported "applied 2 edit(s)".

The panic path is not caught: `fs_tools.rs:584` → `lib.rs:305`, plus the
preview path (`lib.rs:232` → `events.rs:509`), `doomed` (`lib.rs:467`) and the
permission check (`permissions.rs:1252`).

The right order is by descending offset, not by the number in the array.

### 1.2 [critical] `crates/tui/src/lib.rs:606` — the context baseline in characters is subtracted from tokens

Our own bug, from the commit `333dc89` ("Tokens are counted by one counter").

`context_baseline` is filled in **characters** (`forget_counted_context` →
`all_content_chars`), while `raw_content_tokens` subtracts it from **tokens**:
`user.saturating_sub(bu)`. After a compaction the baseline is the whole
previous conversation in characters, and it is subtracted from tokens, so
`saturating_sub` zeroes the counter.

Checked with a probe: a summary of 153 characters (43 tokens) after a
compaction is shown as **0 tokens**. The context panel shows an empty window
after every compaction, and the summary is the only thing the model gets now.

### 1.3 [important] `crates/core/src/loop_.rs:1043` — a service notice counts as a request from the user

`is_prompt` excludes the four nudges, the steer note, the tool picture and the
task note. But it does not exclude:

* the step-limit notice (`loop_.rs:472` — the text says outright "This is a
  notice from the app, not from the user");
* the reminder about an unfinished call (`loop_.rs:871`).

Checked with a probe: `is_prompt` returns `true` for both.

Twelve places hang on `is_prompt`: the cut point at the compaction
(`compact.rs:87`), the midpoint of a turn (`compact.rs:263`), the recap
(`recap.rs:37`), the export (`export.rs:12`), the rewind
(`submit.rs:1224, 1244`), the list of turns (`turns.rs:454`), the session
restore (`sessions.rs:565`), the "is there a turn" check
(`submit.rs:904, 1152`).

How it shows: a turn that ran into the step limit, or a reply with an
unfinished call — in the compaction, the recap and the export the service
notice stands where the request of the owner should be, and the real request
is pushed into the summary.

### 1.4 [important] `crates/tui/src/turns.rs:393` — after `/goal` the autonomous-run block stays in the prompt

`goal_active` is set to `true` when a goal starts (`submit.rs:566`) and to
`false` only on an emergency stop (`events.rs:281`). The normal end of a goal
(`turns.rs:393-413`) restores the mode, the effort and the limits, but does
not do `self.goal_active = false`.

`apply_personality()` (`turns.rs:120`) builds the prompt with
`with_goal_mode(self.goal_active)` — and it is called at `turns.rs:420`, after
the restore. So for the rest of the session the model reads this in the
prompt:

> AN AUTONOMOUS RUN IS UNDER WAY (/goal): There is no user to answer between
> now and the end. … Memory writes are off and questions are not asked …

Meanwhile the status bar and the permission layer already take the goal to be
over.

### 1.5 [important] `crates/tui/src/turns.rs:546` — an error during `/goal` does not restore the state of the goal

The `Err((e, h))` branch of `finish_turn` does neither `goal_state.take()` nor
`set_mode` nor restores the effort and the limits. On a dropped connection or
a 500th error the app stays in goal mode for good: "[Goal: Autonomous]" in
the status, the permission mode "accept all", `remember_mode` stops saving
the change of the mode, and the next turn runs without the limits of the goal.

### 1.6 [important] `crates/llm/src/parse.rs:473` — a "garbage" index splits one call into several

```rust
Some(i) => (i as usize).min(self.tool_ids.len() + 64),
```

The ceiling is counted from the **current length of the table**, and the table
grows with every chunk. The same call, arriving in chunks with the index
`u64::MAX`, gets its **own** index in every chunk: 64, then 129. The arguments
are split between two slots, and the table grows by 64 entries per chunk (the
comment "A garbage index must not grow the table without bound" does not
hold).

In the core (`loop_.rs:658`) every index is a separate call; the call with the
empty name is dropped, the broken one stays → the tool fails with "bad
arguments".

### 1.7 [important] `crates/llm/src/parse.rs:770` — a truncated call closed by a tag **runs**

In `finish()` (line 704) there is an outright ban: "a body cut off
mid-arguments would be 'completed' by repair into something the model never
wrote". The `feed()` path has no such ban, and `repair_json` →
`close_structures` completes the unclosed string and the object.

Checked: `<tool_call>{"name":"write_file","arguments":{"path":"a.md","content":"fn main() {"}</tool_call>`
→ a `write_file` call with the completed content → the file will be written
truncated. The same body without the closing tag is plain text, there is no
call. The same thing is read differently depending on whether the closing tag
made it in time.

### 1.8 [important] `crates/llm/src/repair.rs:368` — the repair loses `\d`, `\w`, `\s`, `\U` and Windows paths

The escape branch carries `\` + the character over as is, so `\d`/`\w`/`\s`/`\U`
stay invalid JSON escaping, and `repair_json` returns `None`.

Checked: `repair_json(r#"{"pattern": "\d+\s"}"#)` → `None`;
`repair_json(r#"{'path': 'C:\Users\me\file.txt'}"#)` → `None`. Then
`effective_args` → `None` → the call is dropped whole ("bad arguments: not a
JSON object"), though it could have been repaired. This is the most common
way the model writes a regex into `grep` and a path into Windows.

Side effect: `normalize_python_dict_and_literals` loses the backslash outside
a string (`{"a": 1\` → `{"a": 1}`).

### 1.9 [important] `crates/llm/src/parse.rs:480` — the "new name = new call" heuristic splits one call into two

If the server sends neither `index` nor `id` but repeats `name` in every
chunk, the second chunk of the same call gets `index = last + 1` → in the
core that is **two** calls, both with broken arguments, and the real call is
lost.

### 1.10 [important] `crates/core/src/loop_.rs:691` — a text call is lost when there is a native one

```rust
if calls.is_empty() { calls = text_calls; }
```

`absorb_scanned` (`loop_.rs:1382`) moves the recognised text call out of the
text into `text_calls` and does **not** leave it in the text. If the same
reply holds at least one native call, the whole `text_calls` is dropped: the
call did not run, it is not in the text, and the model was told nothing.

The comment "Native calls win" describes the case where the server echoed the
same markup, but the code loses *other* text calls as well.

### 1.11 [important] `crates/tui/src/select.rs:110` — the panic "byte index is not a char boundary"

`at` is counted on `lower`, but the slice is taken from `source`; the equality
of the **byte** lengths does not guarantee the same character boundaries.

Checked: `"İaẞ"` → lower `"i̇aß"`, the lengths match (6 bytes), the boundaries
part ways at byte 1. The query `"ß"` → `at = 4` → `text[..4]` panics:
`end byte index 4 is not a char boundary: it is inside 'ẞ' (bytes 3..6)`.

The path is the hidden text of a saved session (the `Ctrl+F` search, the
session picker).

### 1.12 [important] `crates/tui/src/submit.rs:136` — `/cost` does not work during a turn

`while_running()` lists the commands for three states; `cost` is in none of
them. Typing while the model works gives "Unknown command /cost · did you
mean /cost?".

### 1.13 [important] `crates/tui/src/compact.rs:671` — the cost is lost when the summary is made part by part

`summarize_in_parts` adds up the cost of the parts, but returns the cost of
the last (summary) call only. `finish_summary` takes `input_tokens`/
`output_tokens` from that for the "N in · M out" card — it shows the cost of
the summary request alone instead of all N+1. The tokens actually spent are
3–5 times what is shown.

### 1.14 [important] `crates/tui/src/submit.rs:475` — a picture is attached against the documentation

The doc comment: "Only a path typed out on its own attaches a picture; a file
named in a sentence is a mention". The implementation attaches the picture
for **any** token with a `/` or a `\`, and the path stays in the text of the
message.

How it shows: "look at /home/me/shot.png" silently uploads the picture to the
model (traffic, tokens, money).

### 1.15 [important] `crates/llm/src/parse.rs:313` — part of the usage is lost

* The `cached` chain: `.and_then(Value::as_i64)` is applied to the whole
  chain, and a non-numeric `cached_tokens` breaks it — `cache_read_input_tokens`
  and `timings` are no longer looked at, and the share of the cache is lost.
* `cache_creation_input_tokens` ("written") is not read at all, even though
  Anthropic-style usage in the OpenAI shape sends it → `prompt` comes out too
  low.

### 1.16 [important] `crates/llm/src/text_tools.rs:43` — the history the model sees differs from what ran

The history is written through `repair_json`, not through `effective_args`:
the aliases (`filePath` → `path`) are not renamed, and unreadable arguments
are replaced with `{}`. In the next message the model sees a call without
arguments — different from what the permission check, the card and the tool
itself read.

### 1.17 [important] `crates/core/src/loop_.rs:871` — the reminder stays in the history for good

All the other nudges go into `transient` and never reach the history (their
doc comment at `loop_.rs:1227` says outright "Never stored, like the stall
nudge"). This one — `history.push(ChatMessage::user(nudge))` — stays and is
sent again in every following request. On top of that `is_prompt` does not
cut it (see 1.2).

### 1.18 [important] `crates/tui/src/overlay_keys.rs:692` — Enter in the list of sessions takes the wrong session

On Enter, `session_menu_key` takes `menu.selected_value()` regardless of the
filter. `SelectMenu::selected` is an index into the original list, and when
the filter matches nothing it is kept. Filter by a name that does not exist
and press Enter, and the owner opens the session that was selected before the
filtering — with no warning at all.

### 1.19 [important] `crates/core/src/prompt.rs:268` — the prompt promises "Accept All runs both", and the blacklist still asks

The PERMISSIONS section: "Four modes: Planning reads only; Manual asks before
anything that is not a read; Accept Edits runs file changes and asks for the
shell; **Accept All runs both**".

But `permissions.rs:1101-1112`: a command from the blacklist (`rm -rf`,
`git push --force`, `dd`, `sudo`…) in Accept All mode gives
`Verdict::NeedApproval` — a card. The behaviour is deliberate (there is a
test `the_blacklist_outranks_bypass_mode_and_a_standing_always_allow_rule`,
`permissions.rs:1710`), but the model does not know about it: it reads "Accept
All runs both" and expects the command to pass silently — and gets a question
it has nothing to answer with.

### 1.20 [important] `crates/tools/src/fs_tools.rs:679` — the rewind does not restore the file whose write failed

On a write error only `planned[..i]` is rolled back — the earlier **files**.
The `target.file` itself is not restored, and `std::fs::write` is `File::create`
(O_TRUNC) + `write_all`: on a write error (ENOSPC, EDQUOT, EIO) the file
stays truncated or half-written.

How it shows: a batch edit where the write of the second file fails halfway →
the first is restored, the second is cut short; the model gets "nothing was
changed", and a broken file lies on the disk.

### 1.21 [important] `crates/tools/src/image_tool.rs:90` — the size of the picture is checked after the file is read

`std::fs::read(&path)` reads the file whole, and only then does
`bytes.len() > MAX_BYTES` refuse. The limit of 8 MB does not protect the
process.

How it shows: `view_image` on a log or a dump — the process swallows the whole
file into RAM (an OOM for a multi-megabyte one) and still gets a refusal.

### 1.22 [important] `crates/tools/src/git.rs:19` — the `git` commands run without a timeout

`cmd.output()` blocks until the end of the process. For `git status`/`git diff`
that can be long (a huge repository) or endless (waiting for `index.lock`, if
an IDE works in parallel). Unlike `run_shell`, git has neither a timeout nor a
background mode — the turn never ends.

### 1.23 [important] `crates/svc/src/updater.rs:315` — the integrity check of the update is optional, there is no signature

`published_checksum` returns `None` if the release has no asset named
`SHA256SUMS`, and then `check_checksum` leaves with `Ok(())` — the binary is
installed with no check at all (TLS only). There are no signatures
(GPG/minisign) at all. On unix there is no spare copy either: if `fs::rename`
falls over and `fs::copy` fails, the old binary is already truncated and is
not restored; the temporary file is not removed on error.

### 1.24 [important] `crates/tui/src/tasks_view.rs:115` — the top border of the `/tasks` panel is measured in bytes

`"\u{2500}".repeat(inner_w.saturating_sub(title.len() + 1))` — `title.len()`
is bytes, and the title after the translation is "Background tasks": 16 cells,
29 bytes. The top border gets 13 strokes fewer than it needs, and the frame
**does not close**. The other panels measure it right (`chars().count()` /
`visible_width`); here it is bytes.

### 1.25 [important] `crates/tui/src/i18n.rs:1053` — the translation lost the hole `{protocol}`

In the table `("{preset} · {protocol} chooses its own", "{preset} · chooses its own")`
— the Russian side has no `{protocol}`, so the substitution in `settings.rs:271`
does nothing. The settings line shows "Preset · chooses its own" instead of
"Preset · Anthropic chooses its own": it is not clear which protocol the
preset belongs to.

### 1.26 [important] `crates/tui/src/rules_view.rs:106` — one press wipes every standing permission

The comment: "The keys are held down so that a stray press does not take
away a rule that was there for a reason". The code returns `ClearAll` on a
**single** press of `x` or `D` — no holding, no confirmation. A stray `x` in
the `/rules` panel removes every "always allowed" the owner had given.

(Our own, from the commit `1b17a81`.)

### 1.27 [important] `crates/tui/src/tool_views.rs:658` — phrases that are in the table but are not translated

`CallState::Waiting => tr("Waiting on")` — while `Running`, `Ran`, `Failed`
stay bare literals, though they are in the table ("Running"/"Ran"/"Failed").
The same: `tool_cards.rs:319` ("Running"), `:125` ("staged git diff"), `:99`
and `:462` (the literal "project", which the table translates), `:425`
("Editing"), `:600` ("Edited"), `:551` ("stopped"), `agents.rs:23` ("stopped").

In the Russian interface these words stand in English in the middle of a
Russian phrase. The collector does not see them: it looks for the phrases
that are **not** in the table, not for the ones that are there but were never
looked up.

### 1.28 [important] `crates/tui/src/lib.rs:1565` — the expanded card of a thought has a hard minimum width

`width.saturating_sub(4).clamp(30, 84)` — `.clamp(30, …)` overrides the width
of the terminal. Below 34 columns the card is wider than the window, and the
right wall is cut off. The same minimum width is in every panel:
`select.rs:298` (24), `context_modal.rs:19` (20), `mcp_view.rs:356` (20),
`tasks_view.rs:104` (20), `memory_view.rs:310,399` (24), `sampling.rs:281`
(20), `tool_views.rs:98` (16), `whatsnew.rs:303` (14).

### 1.29 [important] `crates/tools/src/fs_tools.rs:584` and `:154` — the write of a file is not atomic and has no rollback

The file is overwritten whole through `std::fs::write`. On a failure (disk,
permissions, the process dying) the content is lost for good. For a single
edit there is no rollback at all, for a batch there is one, but it is
incomplete (see 1.20).

### 1.30 [minor] `crates/llm/src/openai.rs:70` — the learned `token_cap` **adds** `max_tokens` to the request

With `options.max_tokens == None` `map_or` gives `cap` → the body carries
`max_tokens: 68094` (the number from the text of the 402 error), although the
owner of the limit never set one.

### 1.31 [minor] `crates/llm/src/repair.rs:301` — `effective_args` loses the whole object of the arguments

If the value under the name of the tool is not an object, the function returns
`None` instead of the original object:
`effective_args(r#"{"run_shell":"ls"}"#, "run_shell")` → `None`. The call
fails with "bad arguments" instead of the normal error of the tool.

### 1.32 [minor] `crates/core/src/permissions.rs:249` — "Always" may not fire on Windows

`allow_always` splits the command through `parse_chain` (always Posix), while
`decide` checks through `shell_dialects()`, where on Windows (before
`set_shell_dialect` is called) there is `Cmd` too, and in Cmd `;` is not a
separator. The command `a; b` is kept as two exact rules, the check under Cmd
sees one segment → the rule does not match → the card asks again, though the
owner said "Always".

### 1.33 [minor] `crates/core/src/memory.rs:184` — the block of memory can exceed its limit

`PREAMBLE = 32`, and the preamble text itself is about 90 tokens. For a
document that degraded to an "outline", the budget **does not shrink**: the
cost of the outline is not counted at all. The block goes into the system
prompt, which is itself limited by `PROMPT_CEILING`.

### 1.34 [minor] `crates/tui/src/sessions.rs:457` — "N messages" without a declension and without a translation

The other lines of the list of sessions are translated; this one is not. In
the Russian interface you can see "1 messages".

## 6. What was checked and came out clean

So that the report does not read as one long list:

* **Retries.** `Client::post` repeats only on 429/502/503/504/529 and on the
  connect errors — strictly before reading the body. The protocol loops
  (OpenAI 400/422/402, Gemini 400, Anthropic 400/401, Ollama 400) resend only
  the **unsuccessful** answer, before the stream. The invariant "one request —
  one set of events" holds (the test `client.rs:659`).
* **One call never runs twice** on the normal paths.
* **`SseDecoder`** correctly joins CRLF/CR/LF, the BOM, the multiline `data:`,
  the `data` without a colon and the `[DONE]` without the closing empty line.
* **The sandbox of the project.** `path_is_inside` splits the path into
  components and canonicalises each one — a symlink from inside the project
  to the outside is detected correctly; an unresolved symlink counts as
  "outside the project".
* **`repair.rs:234`** (`obj.remove("edits").unwrap()`) is safe: `contains_key`
  is checked a line above.
* **Slices with computed bounds** — 30 places checked: the bounds are
  computed from the same data as the length (`line_span`, `sgr_sequence`,
  `anthropic`'s `assistant_blocks` with a check of the sum and of the UTF-8
  bounds).
* **The translation table** — 889 pairs, none empty, no duplicates, no
  repeated keys; 7 pairs, where the translation equals the English, are on
  purpose (the names of the parameters "Top P", "Top K", "Min P", the
  abbreviations of MCP, the format `{label} {mode}`).
* **Duplicates of the bodies of the functions** — 7 groups over 85 thousand
  lines; only one of them is a real duplication (`write_private`).
* **`unwrap`/`expect` in the production code** — three places, all of them
  safe or deliberate.
* **Locks across `await`** — not one: every guard is released before the
  wait.
* **The updater** checks the SHA-256 against the manifest of the release
  before replacing the binary (but the check is optional — see §1.23).
* **The wrapping of the lines** (`markdown.rs`, `text.rs::wrap_styled`) keeps
  every word and every escape: the plain one, the wide one and the indented
  one — all three paths are covered by tests.
* **The composer** (`composer.rs`): the column of the cursor, the steps by
  graphemes, the empty lines, `up`/`down` (the column is kept), `home`/`end`,
  `Ctrl+U/K/W` — all as documented.
* **The drawing** (`screen.rs::compose`, `theme.rs::recolor_for`): the
  difference of the lines is counted correctly, an unfinished escape stays as
  it is.
* **`install.sh`** downloads over HTTPS only, checks the SHA-256 and removes
  the temporary folder with a trap.

### Notes on the wording of the report

In places the fixes turned out to be wider than the finding says, and in
places narrower. It is written down so that the report does not mislead
whoever reads it in half a year.

* **§1.5.** In `HEAD` the mode, the effort and the limits of the goal were
  returned in the `Err` branch before too — the block stood before the result
  was parsed. Only `goal_active` was not returned: because of it the prompt
  told the model until the end of the session that the autonomous run was
  still going on. Now the return is one and shared by the three outcomes:
  the turn ended, the turn fell, the turn did not settle.
* **§2.3.** There were not nine checks of `gate.pending()` but seventeen.
* **§1.2.** The context baseline turned out to be not a "number of
  characters" but a boundary: that way the units cannot drift apart again
  under any counting.
* **§1.6.** The ceiling of a broken index could not simply be fixed: all the
  broken indices would land in one slot and two different calls would merge
  into one. The slot is chosen by the low bits out of a fixed range.
* **§1.16.** The divergence was not only in the aliases: the unreadable
  arguments turned into `{}` in the history, and the model saw a call without
  arguments, though the tool got something else.
* **§1.19.** The behaviour of the blacklist is deliberate and was left alone:
  only the text of the prompt changes, so that the model knows what it will
  be asked about.
* **§2.2.** `GOAL_QUESTION_TIMEOUT` and `Client::requests_in_flight` turned
  out to be needed by the TUI — they stayed. "Dead code" in the report meant
  "nobody calls it outside the tests", and that had to be checked, not
  deleted on the first pass.
