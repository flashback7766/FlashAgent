# AGENTS.md — правила для ИИ-агентов в FlashAgent

## Источники истины (читать в этом порядке)
1. `PHILOSOPHY.md` — ЧТО и ЗАЧЕМ. Канон. Противоречие = ошибка агента.
2. `ARCHITECTURE.md` — КАК. Границы крейтов, протоколы, трейты.
3. `ROADMAP.md` — В КАКОМ ПОРЯДКЕ. Вехи, статусы, правило гейта B0.
4. `.agents/rules/` — дисциплина исполнения.
5. `.audit/` — журнал аудита. Только добавление, никогда не редактирование.

## Границы агента
- Агент НЕ меняет PHILOSOPHY.md без явного указания владельца в чате.
- Агент НЕ расширяет скоуп вехи. «Ещё заодно» = нарушение.
- Вопрос архитектуры, где 2+ валидных пути → стоп, варианты + рекомендация + одна строка почему, ждать владельца.
- Каждая веха завершается верификацией с реальным выводом команд, не пересказом.

## Скиллы (система переработана)
Скилл = отдельный файл в `.agents/skills/<имя>.md` с жёсткой структурой:
```markdown
# Skill: <имя>
Trigger: <когда применяется>
Inputs: <что нужно на входе>
Steps:
1. ...
Verify: <команда + ожидаемый вывод>
Forbidden: <чего скилл не делает>
```
Скилл подключается упоминанием имени в задаче. Без Trigger/Verify скилл невалиден и не используется.
Базовый набор создаётся по мере вех (rust-core, ui-render, mcp, release).

## Project audit (система переработана)
- Журнал: `.audit/YYYY-MM-DD-<slug>.md`, одна запись = один сеанс работы.
- Структура записи: `### Status: PASS|FAIL|PARTIAL`, `Decision:` (ID вехи), `Files touched:`, `Verification:` (точные команды + exit codes), `Open questions:`, `Handoff:` (что делать следующему).
- Запись создаётся ДО завершения ответа, не «потом».
- Противоречие между .audit и ROADMAP.md: ROADMAP.md побеждает, аудит — свидетельство.

## Верификация
- Ядро: `cargo test --workspace && cargo clippy --workspace -- -D warnings`
- UI: то же + golden-кадры (`cargo test -p ui --features golden`)
- Ни одна веха не закрывается без фактического вывода этих команд в записи аудита.
